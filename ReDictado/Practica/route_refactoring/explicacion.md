### 1. Métodos de instancia que implementaría la clase Location:
> Analizando el código provisto, se puede observar qué mensajes se le envían a los objetos del arreglo waitPoints (que son instancias de la clase Location). Por lo tanto, Location debe implementar los siguientes métodos:   distanceTo(Location otraUbicacion): Debe devolver un valor numérico (un double o Real) calculando la distancia hasta la otra ubicación pasada por parámetro. Esto se deduce de las líneas 5, 7, 15 y 17 del código original.   middle(Location otraUbicacion): Debe devolver una nueva instancia de Location que representa un punto intermedio entre ambas coordenadas. Esto se evidencia en las líneas 7 y 17, donde al resultado de middle se le encadena inmediatamente un llamado a distanceTo.

### 2. Refactorings que aplicaría para eliminar el código repetido:
> El "code smell" (código duplicado) es muy evidente: toda la lógica del bucle for y la condición if/else para sumar la distancia es exactamente idéntica tanto en fullDistance como en distanceLeft. La única diferencia es que el primero inicia la iteración en 1 y el segundo en currentIdx + 1.   El refactoring fundamental a aplicar es Extract Method (Extraer Método). Consiste en mover el bloque de código duplicado a un nuevo método privado auxiliar. A este nuevo método se le debe pasar por parámetro el índice de inicio de la iteración y el tipo de interpolación (el String param).   Detalle extra de arquitectura: Tener un if que toma decisiones basándose en un String quemado en el código (param.equals("Linear")) es otro problema de diseño. Para solucionarlo completamente, se podría aplicar un patrón Strategy (o Replace Conditional with Polymorphism). Sin embargo, para cumplir estrictamente con la consigna de "eliminar el código repetido", con Extraer Método es suficiente.
